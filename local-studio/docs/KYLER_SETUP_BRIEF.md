## 1. TL;DR
- Camden wants to create **photorealistic images and short videos entirely on the 5090 PC**, directed by
  Claude Code. **No outside image/video AI services.** Everything is generated by open-source models on
  the local GPU.
- Components: **ComfyUI** (local image/video engine) + open-weight models + **ai-toolkit** (LoRA training) +
  this repo (a small Python CLI and Claude Code skills that drive ComfyUI).
- Camden uses it from the **Claude app via Claude Code Remote Control**, so it doesn't matter where he is.
- A **nightly scheduled job** can fine-tune a model (e.g. a consistent likeness of Camden), render a fixed
  test set, and have Claude write a morning report.
- **Main risk: sharing the GPU with the 24/7 agent.** Section 3 covers the go/no-go questions.
- Estimated effort: **2–3 hours**, mostly model downloads (~100–150 GB).

## 2. How it fits together
```
Camden (Claude app, phone/web)
      │  Claude Code Remote Control
      ▼
Claude Code on the 5090 PC, run from this repo's folder
      │  python -m studio ...   (stdlib Python + ffmpeg)
      ▼

      │
      ▼

      │
      ▼

Nightly (Task Scheduler / systemd):  GPU free?  → ai-toolkit LoRA training (optional)
                                     → fixed eval renders → contact sheets
                                     → `claude -p` review → reports/nightly/<date>.md
```
Everything talks over localhost. ComfyUI must **not** be exposed to the network.

| 8 | Power and thermals OK for sustained ~575 W GPU load at night? | Training runs the card at full load for hours. |

### GPU-sharing options (pick one)
- **A. Agent doesn't use the GPU** (e.g. it calls a cloud LLM). No conflict; use freely.
- **B. Agent holds a local model on the GPU.** Choose one:
  - **B1: time-share.** Studio work waits until enough VRAM is free (built in: `gpu.min_free_vram_mb`, `--wait-gpu`). ComfyUI unloads its models after nightly runs (`python -m studio free`). Heavy video waits for quiet hours.
  - **B2: move the agent's model to the 4070 PC** and give the 5090 to the studio.
  - **B3: smaller studio models** (quantized or 5B-class video) sized to the VRAM left over.
- The guard reads `nvidia-smi`. Tune `studio.config.local.json → gpu.min_free_vram_mb / max_utilization_pct` to whatever keeps the agent healthy.

## 4. Install

### 4.1 Prerequisites
- Latest NVIDIA driver; `nvidia-smi` works.
- Git, Python 3.12 (3.11 is fine), ffmpeg (Windows: `winget install --id Gyan.FFmpeg -e`; Linux: `apt install ffmpeg`).
- **Claude Code**, installed per the official docs (https://code.claude.com/docs) and logged into **Camden's** account.

### 4.2 Get this repo onto the PC
Either clone Camden's GitHub repo (`MrAwesome1756/Personal-General-Projects`, folder `local-studio/`, on the branch
Camden gives you, and ask him for access), or unzip the `local-studio.zip` he sends. Put it somewhere permanent, e.g.
`C:\AI\local-studio` or `~/local-studio`.

### 4.3 Run the installer (installs ComfyUI + ai-toolkit in their own venvs; no model downloads)
Windows (PowerShell):
```powershell
cd C:\AI\local-studio
powershell -ExecutionPolicy Bypass -File setup\install_windows.ps1 -InstallRoot C:\AI
#   reuse an existing ComfyUI:  -ComfyDir D:\ComfyUI      skip training tools:  -SkipAiToolkit
```
Linux:
```bash
cd ~/local-studio && bash setup/install_linux.sh ~/ai
```
It writes `studio.config.local.json` (machine paths, git-ignored). Prefer your own install method? That's fine:
just fill in that file with `comfy.dir`, `comfy.python`, `comfy.loras_dir`, `ai_toolkit.dir`, `ai_toolkit.python`.

### 4.4 Start ComfyUI and add the workflows
```
powershell -File setup\start_comfy.ps1        (Linux: bash setup/start_comfy.sh)
```
Open http://127.0.0.1:8188 and follow **workflows/README.md**:
1. Workflow → Browse Templates → **Qwen-Image text to image** → download the listed models → Run once →
   **Export (API)** → save as `workflows/image_t2i.json`.
2. Same for **Wan 2.2 14B image to video** → `workflows/video_i2v.json`.
3. Same for **Wan 2.2 text to video** (or an **LTX-2** template) → `workflows/video_t2v.json`.
4. For the smoke test, put `sd_xl_base_1.0.safetensors` in `ComfyUI/models/checkpoints/`.

Check licenses in **docs/MODELS.md**. Camden's business content should use commercial-safe models (Qwen-Image,
HiDream, Wan). FLUX.2 [dev] is non-commercial.

To keep ComfyUI running permanently: a Scheduled Task "at log on" running `setup\start_comfy.ps1` (Windows), or a
systemd user service (Linux). The nightly script also starts it if it's down.

## 7. Troubleshooting
| Symptom | Fix |
|---|---|
| `torch.cuda.is_available()` false / "no kernel image" | PyTorch without CUDA 12.8+. Reinstall torch from the `cu128` (or newer) index; update the driver. |
| Out of memory | The agent is holding VRAM. Use `python -m studio gpu`, then an FP8/quantized model, `--wait-gpu`, or option B2. |
| `doctor` says missing nodes | Update ComfyUI (`git pull` + `pip install -r requirements.txt`), or install the node pack the template needs via ComfyUI-Manager. |
| Prompt landed on the wrong node | Title nodes (PROMPT, SEED, …) in ComfyUI and re-export, or add a `.map.json` (workflows/README.md). |
| Nightly didn't run | Check `outputs/nightly/scheduler.log` and Task Scheduler history. The PC must be awake and the user logged in (or change the task to run logged-out). |
